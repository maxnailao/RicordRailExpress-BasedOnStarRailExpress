# 服务端部署说明

本目录已经是**按服务器目录结构分好**的部署包，直接把里面的三个文件夹拷到服务器根目录即可。

---

## 一、目录结构（本目录 = 服务器根目录）

```
临时/                                  ← 本目录（部署包）
├── mods/
│   └── Ricord-rail-express-1.0.0.jar    模组本体
├── CS2_box/
│   ├── weapon_case_1.json               武器箱
│   ├── hat_box.json                     帽子饰品箱
│   └── music_box.json                   音乐盒箱
└── config/
    └── shopprice.json                   商店商品与价格
```

**拷到服务器后就是：**

```
服务器根目录/
├── mods/Ricord-rail-express-1.0.0.jar
├── CS2_box/{weapon_case_1,hat_box,music_box}.json
└── config/shopprice.json
```

即：把 `mods/`、`CS2_box/`、`config/` 三个文件夹**合并**进服务器根目录
（同名的 `config/` 要合并，别整个覆盖掉服务器原有的其它配置）。

然后**重启服务器**。

---

## 二、为什么必须手动放这些文件

模组**不会**把它们打包进 jar，也**不会**在文件已存在时更新：

- 箱子配置从 `游戏目录/CS2_box/*.json` 读取，**文件名就是箱子 ID**。
- 商店从 `游戏目录/config/shopprice.json` 读取，逻辑是"**文件不存在才生成默认值**"
  （见 `ShopConfig.load()`）。

**这就是"服务器商店里只有武器箱和武器钥匙、没有帽子箱/音乐盒箱"的根本原因** ——
服务器上那份 `shopprice.json` 是旧版本模组生成的，之后再没被更新过。

⚠️ 服务器上已有 `config/shopprice.json` 的话，**用本包的覆盖**（本包是完整的，
含全部 6 个商品 + 回收价）。改完**必须重启**，配置只在启动时读一次。

## 三、内容清单

### `mods/Ricord-rail-express-1.0.0.jar`
模组本体（`mod id = starrailexpress`，`version = 1.0.0`，约 70 MB）。
由 `./gradlew build` 产出。

### `config/shopprice.json`
当前含 **6 个可购买商品**：

| # | 名称 | 类型 | id | 价格 |
|---|---|---|---|---|
| 1 | 武器箱I | box | `weapon_case_1` | 100 |
| 2 | 武器箱钥匙 | key | `weapon_key_1` | 50 |
| 3 | 帽子饰品箱 | box | `hat_box` | 100 |
| 4 | 帽子饰品箱钥匙 | key | `hat_key` | 100 |
| 5 | 音乐盒箱 | box | `music_box` | 100 |
| 6 | 音乐盒箱钥匙 | key | `music_key` | 50 |

`name` 字段是**服务器直接下发给客户端的显示名**（不走语言文件），想改名直接改这里。

`sellprice` 段是**回收价**：按品级的皮肤回收价、`box_price`（三种箱子的回收价）、
`musicbox_price`（音乐盒回收价 30）。

## 四、部署后自检

1. 启动服务器，日志应出现 `[CS2Shop] Loaded 6 shop items`（数量必须是 6）。
2. 日志应出现 `[CS2Box] Loaded 3 box configs.`（数量必须是 **3**）。
3. 进游戏打开商店，应能看到**武器箱 / 帽子饰品箱 / 音乐盒箱**三种箱子及各自钥匙。
4. 开一个音乐盒箱，确认音乐盒进入音乐盒仓库。
5. **开帽子箱**，确认能抽到新帽子（尤其史诗级的大鸡腿头套 / 王冠 / 教皇冠冕 / 杀人狂面具）。

### 常见问题

| 现象 | 原因 |
|---|---|
| 商店只有武器箱 | `config/shopprice.json` 是旧的，没覆盖 |
| 商店有箱子但名字显示成 id（如 `music_box`） | `CS2_box/<箱子id>.json` 缺失或放错目录（箱子名靠登录时同步） |
| 开箱提示缺钥匙 | 商店里钥匙的 `id` 与箱子 `key_name` 不一致 |
| **新帽子在创造栏/仓库里能看到，但箱子抽不到** | **`CS2_box/hat_box.json` 是旧的**（新帽子没进奖池）—— 用本包覆盖并重启 |
| 改了配置没生效 | 没重启服务器（配置只在启动时读一次） |

### 排查"箱子抽不到某件东西"

奖池来源**只有一个**：服务器上的 `CS2_box/<箱子id>.json`。
模组**不会**在文件已存在时更新它，所以**升级模组不会自动把新物品加进旧箱子**。

检查步骤：

1. 打开服务器上的 `CS2_box/hat_box.json`，搜索那件物品的皮肤 id（如 `hat/hat_ricord_wangguan`）。
2. **搜不到** → 就是这个文件旧了，用本包的覆盖。
3. **搜得到** → 看它在哪个 `*_skins` 层，再确认对应概率字段不为 0。
4. 都正常还抽不到 → 看服务器日志 `[CS2Box] Loaded N box configs.`，`N` 必须是 3。

## 五、给维护者的提示

`临时/` 目录已被 `.gitignore` 忽略（规则 `/.涓存椂/`），所以这里那个 70 MB 的 jar
**不会被 git 跟踪**，可以放心留着。

需要长期纳入版本管理的是 **json 配置**（属于作品的一部分）。
仓库里 `docs/服务器部署文件/` 保存了同样一份配置（**不含 jar**），那份是会进 git 的。
