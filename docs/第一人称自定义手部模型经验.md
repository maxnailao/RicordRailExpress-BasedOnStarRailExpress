# 第一人称自定义手部模型（贴武器握把）实现经验

> 适用场景：给某个武器皮肤（如"星光"刀 `knife_xingguang`）在第一人称叠加**纯代码建模的手掌/手指/拇指**，让它贴住武器握把、随挥砍/刺出动作开合。
> 方案代号 M3：复用原版手臂 + 代码叠加手部几何；只对指定皮肤生效，保留 `ENABLED` 一键回退。

## 一、最终生效的关键结论（先看这个，能少走 90% 弯路）

1. **渲染注入点必须选 `ItemInHandRenderer.renderItem` 的 TAIL**（本项目在 `XingguangItemSpinMixin` 里加 `@Inject(at = @At("TAIL"))`）。
   - 不要用 `PlayerRenderer.renderRightHand`：持星光刀时原版手臂根本不走这条链路（被姿态/接管逻辑影响），注入不触发。
   - 不要用 `renderArmWithItem` 相机空间：其原点在"手臂锚点"（屏幕外角落），手画出来看不见。
   - `renderItem` 的物品空间原点 ≈ 武器握持点/拳头，且屏幕可见，手和刀在同一变换链上，天然跟刀移动。

2. **物品空间坐标轴被旋转过，和直觉不一致**（本项目实测，务必自己重新标定）：
   - `ITEM_X` = 垂直轴：负=上、正=下。
   - `ITEM_Y` = 水平轴：负=左、正=右。
   - `ITEM_Z` = 深度轴：正=后（远离镜头）、负=前（靠近镜头）。
   - **量级极敏感**：此空间 1 单位 ≈ 整个屏幕大小，微调必须用 `0.05 ~ 0.3` 的小数，用 1 以上直接飞出屏幕。

3. **遮挡要两步解决**（缺一不可）：
   - 第一步 `NO_DEPTH_TEST` 渲染层：防止手被不透明刀身按深度剔除。
   - 第二步**双 `endBatch()` 强制冲刷顺序**：`NO_DEPTH` 只保证不被剔除，不保证画在最后；手与刀共用同一 `BufferSource`，若刀几何在手之后冲刷仍会盖住手。解决办法是在 TAIL 里先 `endBatch()` 冲掉已提交的刀，再提交手、再 `endBatch()` 冲手 → 手永远是本帧最后绘制者，显示优先级最大。

## 二、守卫条件（renderItem TAIL 注入里，全部满足才画手）

```java
if (SRE.isLobby || leftHanded || !displayContext.firstPerson()) return;
Minecraft mc = Minecraft.getInstance();
if (mc.player == null || entity != mc.player || !XingguangPoseManager.isXingguangKnife(stack)) return;
XingguangHandRenderer.renderInItemSpace(poseStack, buffer, light, mc.player);
```

- `isXingguangKnife`：`stack.getItem() instanceof KnifeItem && "knife_xingguang".equals(ItemSkinManager.getEquippedSkin(player, stack))`。
- `entity == mc.player` 必须是 `==`（第一人称永远渲染自己的手）；`!leftHanded` 只画主手。

## 三、渲染核心代码（renderInItemSpace）

```java
ResourceLocation skin = player.getSkin().texture();
// 最高显示优先级：先冲掉刀等已提交几何，再单独提交手并立即冲刷
if (buffer instanceof MultiBufferSource.BufferSource flushItem) flushItem.endBatch();
VertexConsumer consumer = buffer.getBuffer(handLayer(skin));
poseStack.pushPose();
poseStack.translate(ITEM_X, ITEM_Y, ITEM_Z);
float s = ITEM_SCALE * (DEBUG_FIXED ? 2.0F : 1.0F);
poseStack.scale(s, s, s);
model.hand.render(poseStack, consumer, light, OverlayTexture.NO_OVERLAY, 0xFFFFFFFF);
poseStack.popPose();
if (buffer instanceof MultiBufferSource.BufferSource flushHand) flushHand.endBatch();
```

`handLayer`（照抄 `TMMRenderLayers.additive()` 的 1.21.1 可编译写法，只把深度改成 NO）：

```java
private static RenderType handLayer(ResourceLocation skin) {
    return RenderType.create("xingguang_hand_nodepth",
            DefaultVertexFormat.NEW_ENTITY, VertexFormat.Mode.QUADS, 256, true, false,
            RenderType.CompositeState.builder()
                    .setShaderState(RenderStateShard.RENDERTYPE_ENTITY_TRANSLUCENT_SHADER)
                    .setTextureState(new RenderStateShard.TextureStateShard(skin, false, false))
                    .setTransparencyState(RenderStateShard.TRANSLUCENT_TRANSPARENCY)
                    .setDepthTestState(RenderStateShard.NO_DEPTH_TEST)
                    .setCullState(RenderStateShard.NO_CULL)
                    .setLightmapState(RenderStateShard.LIGHTMAP)
                    .setOverlayState(RenderStateShard.OVERLAY)
                    .createCompositeState(true));
}
```

## 四、标定流程（下次做皮肤照做）

1. 建 `XingguangHandModel`（`MeshDefinition`/`CubeListBuilder`/`LayerDefinition.create(mesh,64,64)`），注册 `EntityModelLayerRegistry`，用 `Minecraft.getInstance().getEntityModels().bakeLayer(LAYER)`。
2. 在 `renderItem` TAIL 挂上 `renderInItemSpace`，先只画手掌 `model.hand`。
3. 开 `DEBUG_FIXED=true`（放大 2 倍便于观察）。**注意 `entityTranslucent` 的顶点色 tint 不生效**，探针要用"大小"区分身份、别指望染红。
4. **单变量试探定轴**：每次只改一个 `ITEM_*`，看手往哪移动，反推该轴语义（本项目就是这样发现 X=上下的）。
5. **收敛落点**：先垂直（`ITEM_X`）→ 再水平（`ITEM_Y`）→ 再深度（`ITEM_Z`），每步 0.05~0.1 小步，让用户看截图报方向。
6. 落点满意后关 `DEBUG_FIXED`、清掉探针方法，把 `ITEM_SCALE` 定成拳头大小。

## 五、本项目最终参数（星光刀，可作下次起点）

```java
ITEM_X = -0.05F;   // 垂直：略微往上
ITEM_Y = -0.21F;   // 水平：往左贴刀柄
ITEM_Z = 0.1F;     // 深度：往里嵌一点
ITEM_SCALE = 0.6F; // 手掌大小
```

> 换武器/换模型时这些值几乎一定要重标，别直接照抄数值，照抄的是**方法和轴向**。
