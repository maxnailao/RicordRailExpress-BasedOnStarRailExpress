# 添加皮肤资源流程（跨主模组与 ricord_skins 素材包）

新增一款皮肤要同时动**两个仓库**。这份文档是权威流程；素材仓库 `Ricord-Skins/README.md` 只保留素材侧的子集并指回这里。
帽子皮肤的建模细节与箱子概率表见 [添加帽子饰品教程](添加帽子饰品教程.md)。

---

## 一、为什么要分两处

| | 主模组 `starrailexpress`（公开，GPL-3.0-only） | 素材包 `ricord_skins`（私有，纯资源 jar） |
|---|---|---|
| 内容 | 皮肤**引擎**：注册表、模型加载、渲染、状态存储与网络同步、UI、特殊皮肤逻辑、中文名、卡池配置 | 皮肤**素材**：贴图、模型 JSON、皮肤专属音效 ogg、音乐盒 ogg、皮肤显示名与描述、瑞科德饰品物品模型 |
| 谁改 | 加皮肤 ID、进卡池、写特殊逻辑时 | 放美术文件、写皮肤显示名时 |

两条必须知道的规则：

- **素材包里的资源仍写在 `starrailexpress` / `noellesroles` 命名空间下。** Minecraft 按「命名空间/路径」在所有已加载资源包里找文件，与由哪个模组提供无关，所以代码里的 `SRE.id("item/skins/...")` 和皮肤模型内部的贴图引用都不用改。
- **只有 lang 例外**，必须放在 `assets/ricord_skins/lang/`。同一命名空间下同一语言的 lang 文件只有一份生效，放两份会静默互相覆盖。
- 主模组对素材包只是 `recommends` 软依赖：没装也能进游戏，皮肤列表为空、武器回落默认模型、头顶不渲染帽子，日志出现一次 `[SkinAssets] 未找到任何皮肤模型资源`。

## 二、素材仓库（Ricord-Skins）要放的文件

皮肤类型目录名 = 物品的 `getItemSkinType()` 返回值（也是 `ItemSkinManager.SkinTypes` 常量）：
`knife` / `revolver` / `bat` / `grenade` / `hat` / `bow`。（`derringer` 目前没有皮肤，新增此类可换皮武器时另建同名目录。）

| 类型 | 路径（相对素材仓库根） | 说明 |
|---|---|---|
| 贴图 | `src/main/resources/assets/starrailexpress/textures/item/skins/<type>/<skinID>.png` | 2D 皮肤 16/32/64²，3D 饰品帽可 128/256² |
| 皮肤模型 | `src/main/resources/assets/starrailexpress/models/item/skins/<type>/<skinID>.json` | **必须有**，否则该皮肤不会被注册与渲染 |
| 手持变体 | 同目录 `<skinID>_in_hand.json` | 第一/三人称手持外观；缺这个文件对应手持位就是默认模型 |
| 拉弓变体 | 同目录 `<skinID>_pulling_0/1/2.json` | 仅 `bow` / `crossbow` 需要 |
| 显示名 | `src/main/resources/assets/ricord_skins/lang/{zh_cn,zh_tw,en_us}.json` | 键：`screen.sre.skins.<type>.<skinID>.name` 与 `.desc`；**三份语言都要加，键集合必须一致，UTF-8 无 BOM** |
| 皮肤专属音效 | `src/main/resources/assets/starrailexpress/sounds/<子目录>/<name>.ogg` | 只放 ogg；`sounds.json` 条目与 `SoundEvent` 注册在主模组（见第三节 5） |
| 饰品物品模型 | `src/main/resources/assets/noellesroles/models/item/<物品id>.json` | 仅"要出现在创造物品栏的瑞科德饰品"需要 |

> **玩偶方块的贴图（`assets/starrailexpress/textures/block/plush/`）在主模组里，不在素材包。** 这样没装素材包时
> 玩偶方块本身仍正常；皮肤包缺失时 `HatSkinRenderer` 直接不渲染帽子，避免头顶坐一个没戴帽的裸玩偶。

模型 JSON 的写法要点（对照素材包里现有 273 个模型）：

- **2D 皮肤**（刀/球棒/手雷/左轮等）：`"parent": "item/generated"`，`textures.layer0` 指向
  `starrailexpress:item/skins/<type>/<skinID>`。
- **饰品帽**（自己在 Blockbench 调过 `display.head` 的，如瑞科德钢盔）：没有 `parent`，带 `elements`，
  贴图写在 `textures` 的 **`"0"` 与 `"particle"` 两个键**上，都指向 `starrailexpress:item/skins/hat/<skinID>`；
  写全 `display.head` 后走原版头顶物品管线，作者调好的朝向/位置/缩放原样生效。
- **玩偶帽**：`"parent": "noellesroles:block/<base>_plush"` 继承玩偶方块模型（该父模型与玩偶贴图都在主模组），
  但**仍要放自己的贴图**，并在 `textures` 里用 `"0"` / `"particle"` 把父模型的玩偶贴图覆盖成
  `starrailexpress:item/skins/hat/<skinID>`，否则帽子会顶着玩偶原贴图。走玩偶缩放链路。
- **弓**：`textures.particle` 用变量引用 `"#0"`（跟随 `"0"`），三档拉弓写成 `<skinID>_pulling_0/1/2.json`。
- 烘焙脚本会把所有旋转烘进 `from/to`（Java 只允许 ±45/±22.5/0°），别手写 `rotation`。

构建与联调：

```bash
./gradlew modJar              # 产物 build/libs/ricord-skins-<版本>.jar
./gradlew installToMainRepo   # 拷进主仓库 runtime_mods/（已被主仓库 .gitignore 忽略）
```

主仓库脚本（`tools/hat_*.py`）默认把产物写到同级的 `Ricord-Skins`，位置不对时用环境变量 `RICORD_SKINS_ROOT` 覆盖。

## 三、主仓库（starrailexpress）要改的地方

1. **注册皮肤** —— `src/main/java/io/wifi/starrailexpress/index/SRESkinRegistry.java`

   ```java
   registerSkin(SkinTypes.KNIFE, "knife_my_skin", QualityColor.RARE);
   ```

   品级枚举：`COMMON` `UNCOMMON` `RARE` `EPIC` `LEGENDARY` `UNBELIEVABLE`，另有 `LEGACY`（传承，星空曙光卡池大奖这类）。

   > ⚠️ **追加，不要插在中间。** `ItemSkinManager` 给每个皮肤按**注册顺序**分配整数 ID，网络同步（`SREPlayerSkinsComponent`）
   > 传的是这个整数。中间插入会让后面所有皮肤的 ID 错位，表现为玩家装备的皮肤串号。
   > 新增皮肤**类型**时，除了加 `SkinTypes` 常量，还要把它追加到 `ItemSkinManager` 里 `typeOrder` 数组的**末尾**。

2. **中文名与介绍** —— `src/main/java/org/agmas/noellesroles/cs2/CS2SkinInfo.java`

   ```java
   register("knife/knife_my_skin", "我的皮肤", "一句话介绍");
   ```

   开箱/仓库/饰品界面（`CS2WarehouseScreen`、`AccessoryScreen`、`LootScreen` 等 14 个界面）用的都是这里的名字，
   而不是 lang。lang 里的 `.name` 主要给皮肤管理界面与物品 tooltip。**两处都要加**，否则一处显示裸 ID。

3. **要作为物品出现时**（瑞科德饰品这类）
   - 物品注册：`src/main/java/org/agmas/noellesroles/init/ModItems.java`（`"<物品id>", RICORD_ACCESSORIES_GROUP`）
   - 物品模型：见第二节，放**素材仓库**的 `assets/noellesroles/models/item/`
   - 物品名翻译：`src/main/resources/assets/noellesroles/lang/{zh_cn,zh_tw,en_us}.json`（在主仓库）

4. **进卡池** —— `CS2_box/<box>.json`，按品级把 `"<type>/<skinID>"` 放进对应的 `<品级>_skins` 列表
   （`common_skins` / `uncommon_skins` / `rare_skins` / `epic_skins` / `legendary_skins` / `unbelievable_skins`），
   同品级的概率字段 `common` / `uncommon` / … 决定掉落权重（概率表见帽子教程第二节）。

   > 服务器上的 `CS2_box/` 是**手动部署**的配置文件，模组不会更新已存在的文件：改完仓库里这份，
   > 还要同步 `run/CS2_box/`（本地测试）和服务器那份，否则游戏里看不到新皮肤。
   > 内部形态皮肤（`knife_anxing_1/_2`、`knife_emozhidao_2`、`revolver_shengxuan_1/_2`、`revolver_jianshouzhe_1/_2`）
   > **不要**塞进卡池；`AccessoryScreen` 的 `EXCLUDED_FORM_SKINS` / `EXCLUDED_PREVIEW_HATS` 名单也要同步。

5. **皮肤专属音效**：三处齐全才会响——素材仓库放 ogg、`assets/starrailexpress/sounds.json` 加条目、
   `src/main/java/io/wifi/starrailexpress/index/TMMSounds.java` 注册 `SoundEvent`。缺后两处不播放，缺 ogg 静默失败。

6. **特殊皮肤逻辑**（多形态切换、专属音效、拉弓三档、击杀特效等）写在主模组的 handler 里，按皮肤 ID 匹配：
   `util/AnxingSkinHandler` `ShengxuanSkinHandler` `SushuiKunaiSkinHandler` `SushuirenSkinHandler`
   `EmozhidaoSkinHandler` `JianshouzheSkinHandler` `ShenfaBowSkinHandler`，
   以及 `client/XingguangClientEffects` / `XingguangPoseManager` 与 `mixin/client/ShenfaBowOverrideMixin`。
   **这些代码留在主模组**：它们依赖主模组的网络包、mixin 与注册表，挪进素材包会引入跨模组加载顺序问题。

## 四、加完之后怎么确认

```bash
# 1) 两个 jar 都能构建
cd Ricord-Skins && ./gradlew installToMainRepo
cd ../RicordRailExpress-BasedOnStarRailExpress && ./gradlew build

# 2) 皮肤素材不该再出现在主模组 jar 里（应为 0）
unzip -l build/libs/Ricord-rail-express-*.jar | grep -c "item/skins"

# 3) 帽子饰品专用一致性校验（皮肤模型/物品模型/注册/中文名/物品名/卡池，双 jar 一起查）
python tools/hat_verify.py --jar build/libs/Ricord-rail-express-1.0.0.jar
```

> `hat_verify.py` 会同时读 `CS2_box/hat_box.json` 与 `run/CS2_box/hat_box.json` 并比对两处是否一致，
> 本地没跑过服务器时后一份不存在，脚本会抛异常。先 `mkdir -p run/CS2_box && cp CS2_box/hat_box.json run/CS2_box/`
> 再跑（`run/` 已被 `.gitignore` 忽略）。

再手动核对这一条链是否闭合：**注册表 ID ↔ 素材文件 ↔ lang ↔ CS2SkinInfo ↔ 卡池列表**，
五处的 `<skinID>` 拼写必须完全一致（皮肤名一律小写下划线）。

游戏内验收（把素材 jar 放进客户端 `mods/` 或主仓库 `runtime_mods/`）：

| 检查项 | 怎么看 |
|---|---|
| 拿到皮肤 | `/tmm:skins give <玩家> <type> <skinID>`，或 `/tmm:skins give <玩家> all` 全给一遍 |
| 查看已解锁/装备 | `/tmm:skins <玩家>` 打开皮肤管理界面（键位 `key.starrailexpress.skins`） |
| 武器皮肤 | 手持切换主副手看 2D 与 `_in_hand` 两个变体；弓看拉弓三档 |
| 帽子 | 第三人称或旁观者视角看头顶；饰品帽核对 `display.head` 朝向，玩偶帽核对缩放 |
| 名字 | 皮肤管理界面（lang）与仓库/开箱界面（CS2SkinInfo）都要是中文名，且切 `zh_tw` / `en_us` 各看一遍 |
| 卡池 | 打开对应箱子，新皮肤出现在正确品级格子里；奖池浏览界面能看到它 |
| 降级 | 把素材 jar 移走再启动：能正常进游戏、皮肤列表为空、无缺失模型刷屏、无异常栈 |

`/tmm:skins` 需要 `officialVerify` 且 `hasPermission(2)`。

## 五、发布注意

- 素材 jar **只发客户端**；服务端不加载模型与贴图，装了也无害（`environment` 为 `*`）。
- **不要**把 `ricord_skins` 加进 mod 白名单的哈希校验列表（`STARRAILEXPRESS_HASH_MOD_IDS`），
  否则没装皮肤包的玩家会被判"应装未装"踢下线，与软降级自相矛盾；确实要强制时，
  在服务端 `config/mod_whitelist/` 登记该 jar 的 SHA256。
- **版本要联动**：改了 `SRESkinRegistry`（哪怕只是追加）就要同时发新的主模组 jar；只改素材（贴图/模型/显示名）
  只需重发素材 jar。两端注册表版本不一致会导致整数 ID 错位。

## 六、常见坑

1. **同一路径两个仓库都放一份**：按资源包顺序只有一份生效，另一份静默失效。素材搬走后确认主仓库该路径已空
   （`.gitignore` 已把这些路径列为忽略，误放回来的文件不会被 git 提示，但会被 `processResources` 打进 jar）。
2. **只加了 lang 没加 `CS2SkinInfo`**（或反之）：一处显示中文、一处显示 `knife_my_skin` 这种裸 ID。
3. **lang 三份不同步**：切语言时缺键回退成裸 ID。三份键集合必须完全一致。
4. **UTF-8 BOM**：语言文件不允许带 BOM。
5. **在 `SRESkinRegistry` 中间插入**：整数 ID 全部后移，玩家装备的皮肤串号。
6. **帽子没有模型 JSON**：素材包在时也会取不到模型——饰品帽直接不显示，玩偶帽回退成裸玩偶。
7. **`_in_hand` 漏了**：手上和地上/物品栏里的外观不一致。
8. **音效只放 ogg**：`sounds.json` 与 `TMMSounds` 都在主模组，缺任一处不会响。
9. **把皮肤注册表/皮肤清单挪进素材包**：目前刻意不这么做。跨模组后两个 entrypoint 的加载顺序不受控，
   而皮肤整数 ID 依赖注册顺序；真要挪，得先改成注册收敛后按名字排序再分配 ID。
